# 共享骨架与网格局部骨骼索引

现行蒙皮绑定契约；初次实现于 v43。当前实现与验收状态见[文档索引](README.md)。

本文记录 v43 沿用源骨架的实现。v48 新增骨骼及 Skeleton 驱动扩展见 [骨架驱动](skeleton-driving.md)，
原槽、原 bind pose 保留及实例隔离原则不变；不能把新增节点建立成功当作 GPU 蒙皮已验证。

## 规则

一个部位可以使用同一角色共享骨架中原部位没有用过的骨骼。
Mesh 的骨骼索引指向该 Mesh 的局部表，不是角色骨架的全局序号。
局部表的第 i 项必须同时对应权重索引 i、bind pose i 和当前 Renderer.bones[i]。
两个实例可以共享同一个 Mesh 资源，但必须分别绑定自己的骨骼 Transform，不能共享实例数组。

原骨骼槽及其绑定矩阵逐项保留，包括删面后零权重的槽。额外骨骼追加到表尾；
不用改 INI，不要求用户手写索引，不更改相机关闭表达 `skip` 的约定。

## v43 根因与实证

- 用户按 F10 后，日志确认加载了 typhoeus body：14,665 顶点、78,480 索引。
  因此本次拉伸不能继续解释为未加载 Mod。
- Blender body 有 76 个顶点组、62 个正权重骨骼，均属于同一个 316 骨骼的共享骨架。
  原部位局部表只有 35 项。旧导出器用 `if name in bone_index` 过滤，静默丢弃了表外的组。
- 旧导出有 7,911 个绘制顶点的四项权重全零；Blender 原顶点并非全零。
  例如顶点 126 原为 Pelvis 权重 1，旧文件却是四个零。不是删面或接缝本身破坏权重。
- 仅放大 bones 数组不足以修复：新骨骼需要正确的 inverse bind matrix。
  对原 35 槽测试 `W_bone * D_original`，PFB 初始 TRS 与原 Mesh 的绑定姿态不完全一致，
  最大偏差约 0.04213。禁止因此统一重算原槽。
- 不同源部位的原绑定矩阵经共同骨骼坐标变换后兼容，实测最大偏差约 1.19e-7。
  当前 body 所需新增 41 项都能从同骨架其他部位的原绑定信息获得。

## 实现

Blender：

1. 以完整 `eiem_bone_paths_json` 为身份，原槽位和原矩阵不变；数字 palette 不再决定原槽身份。
2. 读取同骨架的原绑定记录。新导入将这些记录持久化到骨架数据块，删除 donor 物体不丢记录；
   旧工程从仍存在的源物体元数据获取，导出不改作者对象。
3. 不同部位使用共同骨骼 a 换算绑定空间（矩阵为列向量、文件 16 项按列存储）：
   `C = inverse(D_donor[a]) * D_target[a]`，`D_target[b] = D_donor[b] * C`。
   共同槽不一致时明确报错，不选一个矩阵强行继续。
4. 从未被任何源网格引用的骨骼没有原 Mesh bind pose，才根据源骨架 TRS 和已知祖先绑定生成新槽。
   没有源 TRS 的全新骨骼明确报错，不填单位矩阵。原有矩阵永远不被这一步覆盖。
5. 按实际顶点组写权重，接缝顶点复制同一份结果。当前文件固定四影响；超过四个取最强四个归一化，
   控制台报告数量；源工程不改。正权重组不存在或有面顶点无权重时明确拒绝，不输出零权重蒙皮。

DLL：

1. Mesh 资源缓存保存原文件槽序以及不可变路径/哈希，删除旧的原部位等长调色板重排逻辑。
2. 从命中 Renderer 的原骨骼路径锚定当前实例的共享骨架根，只遍历该根；不扫描其他角色，
   不按角色/PFB 名称硬编码。完整路径唯一匹配后形成 Mesh 顺序的 Transform 数组。
3. 先准备与验证数组，再写 Mesh 和 bones；数组在 Unity 调用期间及使用期间均有托管引用保护。
   原始数组单独保存，不能被新数组覆盖为恢复基线。
4. 游戏后续 bones setter 刷新只重申该实例当前拥有的替换数组；F10 恢复期间禁止重申。
   撤销先恢复源 Mesh/骨骼，确认成功才释放引用；失败保留基线并报告。实例销毁释放其记录。
5. partner 使用源实例同一骨架解析自己的 Mesh 表，不篡改源 Renderer 的骨骼数组。

## v43 验证记录及适用边界

- 新后台 Blender 回归在旧实现首先复现 2 槽而预期 5 槽，再验证修复。
  包含原零权重槽、表外骨骼、不同绑定空间、骨架保存记录、删除 donor、无效组拒绝、四影响限制、
  重复输出一致及作者数据不变。
- 提取实际 DLL resolver/赋值函数做原生测试：表外骨骼、两个同路径不同实例、缺失路径、
  失效骨骼、setter 失败、重复应用与引用释放。资源缓存测试验证命中时也返回绑定身份。
- 实际恢复函数回归：扩展数组恢复原数组，失败保持两份引用，成功后各释放一次，多次 F10 不重复释放。
- v43 验证时的 body 临时导出：14,665 顶点、76 槽，零权重绘制顶点 **0**，逐顶点映射差异 **0**，
  原 35 槽与矩阵不变。315 个源顶点超过四个影响，输出使用最强四个；此限制不是无损保留全部影响。
  作者几何、顶点组/权重、选择、显隐与对象属性未变。没有覆盖游戏 Mod 或 `.blend`。
- 上述是离线/适配器测试，不模拟游戏自定义 GPU 缓冲区注册，也不能证明游戏画面已不拉伸。
  v43 新骨骼容量的游戏蒙皮、切地图、角色 UI 验收需另外记录。
- 当次 body 编辑数据没有切线属性，骨骼修复未包含切线生成。后续 0.11.1 已在导出端补齐缺失切线生成，
  保留有效源切线；当前行为与历史证据见 [顶点数据契约](vertex-data-contract.md)。

旧文件里已丢掉的表外权重不能由 DLL 猜回；升级 Blender 后重新导出所选部位，配套加载 v43。
F10 只重载配置和资源，不更新 DLL。部署与游戏验收记录分开，不因编译通过标为游戏成功。

历史测试和部署结果见[版本记录](archive/release-records.md)。
