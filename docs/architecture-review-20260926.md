## 本轮修正

| 问题 | 条件与影响 | 修正和验证 |
|---|---|---|
| 模型 owner 固定四槽 | 同一模型有五个以上 owner 时，后来的 owner 被静默丢弃；前四个释放后可能提前退役仍在使用的模型 | 改为动态集合；宿主测试登记六个 owner，释放前五个后确认模型仍保留，最后一个释放才退役 |
| 轻量输入吞掉蒙皮刷新 | Reapply 与 SkinRefresh 合并后，形态键、submesh 或失效输入的提前返回会消费请求但不执行模型回放 | 所有生命周期刷新都阻止轻量提前返回；测试失效输入与 SkinRefresh 同批时仍执行回放并清空刷新集合 |
| 按住按钮合并身份不足 | 相邻 hold 事件仅比较 Mod 和快捷键；同快捷键的不同 Key section 可能被合并到错误按钮 | 合并条件增加 Key section；队列测试确认同 section 合并、不同 section 保持顺序 |
| 管理器控件跨 Mod 共享身份 | 两个 Mod 使用相同变量或 Key section 名称时，ImGui 控件可能沿用前一 Mod 的状态 | 控件 ID 加入完整 Mod 路径 |
| 隐藏 UI 做无用工作 | 游戏失焦或最小化时仍复制各 Mod 的 Lua UI 状态并处理代际变化 | 在读取快照前暂停；恢复焦点后读取最新代际，F10 资源刷新不受影响 |
| 文档与实现不一致 | 文档称非法 Mod 不保留旧动作，实际协调器会拒绝整代候选并保留旧状态 | 更新当前配置文档；历史调查放入 archive；当前文档链接检查无悬空引用 |

队列还合并相邻滑块写入，保留按键边界和代际边界。普通构建关闭高频诊断 Hook，Mesh 校验、四槽修正、材质提交和三端生命周期 Hook 仍保留。

## 仍需处理的边界

1. **装配失败已添加即时恢复和代际门控，仍需游戏验收。** Mesh、bones、形态键、材质和 enabled 的宿主故障注入已覆盖提交失败、成功恢复及恢复失败保留引用。F10 恢复不完整时不发布新代，并回放可恢复实例的旧规则。多个 Unity setter 依然不能成为真正的原子操作；游戏内跨世界/UI/NPC 的时序和错误注入未验证。
2. **Native Mesh 私有布局依赖游戏版本。** 当前有 UnityPlayer 版本、vtable、getter 和载荷校验，不匹配时拒绝替换。未来游戏更新需重新验证；这项不能用“移除硬编码”简单删除，否则失去受检验的躺地修复。
3. **资源路径与编码的剩余边界。** 中文游戏目录、Mod 目录、资源路径和 section 已通过 Unicode 宿主测试。`mod.ini` 缺失与存在但不可读现已区分；后者拒绝 F10 候选。`MAX_PATH` 固定的 Mod 身份字段、长路径、联接目录和重命名仍未验收。
4. **旧实验源码仍与宿主层同文件。** 高噪声探针关闭后不应进入热路径，但 `il2cpp_trace.h` 仍过大。下一步按完整模块提取 model registry、world/UI adapters，再将诊断放入独立构建单元；原始证据保留在归档中。
5. **性能结论需要实测。** 已减少重复层级快照、连续输入和普通成功日志；尚未取得多角色场景的帧时间／F10 峰值／长期内存数据。F10 必须每次完整刷新，性能优化不能改变此契约。
