# Blender 网格切换作者流程

当前作者端：Blender 插件 **0.11.1**，按显式选择导出，相机关闭表达游戏隐藏；导出自动拆分面角接缝顶点。
新增形态键的自动控制、稳定变量身份、玩家状态保存和独立材质导入见 [作者状态](author-state-materials.md)。
共享骨架的现行绑定契约见 [骨骼绑定记录](shared-skeleton-binding.md)。原相机/skip 规则不变。
工作区实现与游戏验收状态统一见[文档索引](README.md)。

## 目标与职责

用户只在 Blender 内拆分/编辑网格、组织状态、填写快捷键，然后导出一个 mod。
DLL 继续使用 [条件与按键语法](conditional-keys.md)，不为 Blender 增加另一套运行时语法。
`.blend` 保存切换组/状态/对象关系等语义数据，不保存一份等待字符串替换的 INI。
升级导出器后，旧工程可重新导出；本功能不要求修改 Mesh 二进制格式。

## 最小操作模型

- **切换组**：例如“上衣”“饰品”，各有一个快捷键和初始状态。组之间独立。
- **状态**：组内的一个可选款式，可以包含多个网格；空状态表示这组不显示任何网格。
- **网格**：通过 Blender 集合归属状态；同一个对象只能属于一个切换状态。
- 只处理所选网格，不自动补选同源物体或其他切换状态成员。
- 所选网格的对象相机开关开启时正常导出；关闭（`hide_render=true`）时表达游戏隐藏，
  不导出其网格/材质/贴图/形态键依赖。不在切换组中的相机开启部件保持常显。
- Blender 眼睛/显示器隐藏只用于编辑/预览，不决定游戏显隐。
- 未选中的独立源资源不生成规则。材质与贴图仍按所选可绘制物体的实际依赖导出。

使用实际集合表达结构，Outliner 可见且允许改中文名称：

```text
EIEM 切换
  上衣（F6）
    显示          ← 多个上衣部件
    隐藏          ← 空集合
    款式2         ← 可选，另一些上衣部件
  饰品（F7）
    显示          ← 多个饰品部件
    隐藏
```

3D 视图侧栏 N → EIEM → 网格切换：

1. 原网格在编辑模式下选面，用 `P → 选中项` 分离，回到物体模式。
2. 选中要一起切换的部件，点击“从所选创建切换组”。自动建立“显示/隐藏”两个状态，所选进入显示。
3. 填组名、快捷键；默认初始状态为显示。可添加款式状态，将所选网格分配给它。
4. 另一部分重复操作，使用另一快捷键；一键设置初始状态，一键预览，另有恢复预览按钮。
5. 选择需要导出的全部网格/款式（包括需要游戏隐藏的物体），文件 → 导出 → EIEM package。
   只导出当前选择，不会替用户选中其他部件。N → EIEM 的“游戏隐藏（相机）”与对象相机图标是同一属性。

不在 Blender 注册游戏的 F6/F7，避免抢占 Blender 自身快捷键；用面板预览状态。
预览只修改当前视图层的临时显隐，并可恢复原值，不改网格、材质、权重或导出初始状态。
全局刷新键仍由游戏的 `plugin/eiem.ini` 配置，不复制到每个 mod。

## 导出与 DLL 对接

- 拆分生成的数据块通常保留相同源资源信息，但不再是同一份几何；自动分配唯一导出资源段/文件名。
- 以原 Mesh 选择器分组。同源部件只生成一个命中 Render，避免第一条规则命中使其余部件失效。
- 所选源物体全部相机关闭时，仅生成一个 `handling=skip` 命中 Render，不生成资源文件。
- 多部件或受按键控制时，该命中 Render 始终 `handling=skip` 隐藏原件，通过 `partner.N` 装配所选相机开启部件。
  每个 partner 对应独立 Render 模板，拥有自己的 mesh、材质槽；组内条件决定哪些 partner 存在。
- 单个未设切换的对象保持现有 `mesh=...` 原 Renderer 替换流程，不强迫所有 mod 使用 partner。
- 切换为隐藏时只移除该状态的 partner，不重新显示完整原衣服；常显部件和其他组不受影响。
- 新 Renderer 继续复用源模型实例及其骨架，由现有运行时处理蒙皮/材质和销毁；不复制角色或骨架。
- 自动声明 `[Constants]`、`[Key...] type=cycle`，用数字状态和 `if/endif`；组/状态显示名仅作注释。
  相机关闭是无条件隐藏，不为该部件生成 partner；只有隐藏部件的切换组不生成无效按键。
- F10（或用户设定的刷新键）重新读取 mod 后保留玩家的切换状态；未保存过时使用 Blender 初始状态。
  0.9 导出持久化变量，组和款式编号随 .blend 保存；重排款式不重新编号。删除已保存款式后可用恢复默认值重选。
- 物体范围严格等于所选物体，0.8.1 移除了自动扩展同源和切换组物体的闭包。
  仅保留所选可绘制网格的材质/贴图依赖。导出前显示所选、隐藏、源资源和切换组数量。
- 同源拆分的几块在游戏里仍是一个源 Mesh。导出该源的新几何会整体替换源几何，
  要保留的拆分部件必须一起选中；未选部件不会自动恢复原 Mesh 中的对应部分面。
  这不同于“另一个独立源 Mesh 未选中”，后者不会生成规则。
- `.mesh` 保持独立资源；只输出引用到的修改材质和新增贴图。partner 改用了不同原材质槽时必须显式导出
  该材质克隆，不能仅因为材质参数未变就遗漏槽位分配。

示意（导出器自动生成，无需手写）：

```ini
[Constants]
$switch1=0
$switch2=0

[KeySwitch1]
key=F6
type=cycle
$switch1=0,1

[KeySwitch2]
key=F7
type=cycle
$switch2=0,1

[RenderSource1]
asset=OriginalMeshName
handling=skip
partner.0=RenderAlways
if $switch1 == 0
    partner.1=RenderTop
endif
if $switch2 == 0
    partner.2=RenderAccessory
endif
```

RenderAlways/Top/Accessory 为普通独立 Render 模板，各自引用声明好的资源，不再带命中选择器。

## 校验边界

导出前报告：同一对象在多个状态、空切换组、快捷键非法/组之间重复、缺失源 Mesh 身份、超出运行时
partner 上限。一次无效配置不能先清空已有导出。导入的原骨骼调色板与零权重顶点组仍保留，拆分不重排。
外部网格必须先完成权重/源资源绑定；本功能不自动猜测骨架映射，也不偷偷合并网格。
同名但来自不同作者包的源资源不自动合并；一次导出若对同一命中资源有多个不相容来源，明确报错。

使用 `.blend` 保留作者工程。新增条件 INI 是运行产物，不承诺把手写的任意 if 程序反编译成集合；离线
静态资源包导入流程不变。用户应重新打开 `.blend` 编辑切换，而不是将产物当作唯一工程文件。

## 验收要求

### DLL 装配检查发现的配套修正

现有 partner 创建代码只是将新物体放到源物体的父节点，并没有调用已有的 Transform 拷贝函数，
因此新物体可能停留在错误位置。本轮改为挂在源 Transform 下、局部单位变换，天然随源 Transform 运动，
不新增逐帧同步器。另一个问题是 partner 指定部分材质槽时从空数组构建，会丢失未改的源材质槽；
改为复用源 Renderer 材质数组的克隆/覆写方法。这不代表游戏自定义 GPU 管线中所有 Renderer 私有状态均已验证。
重应用时按对象所有权排除插件生成的 Renderer，避免它们使用同源 Mesh 名称时再次命中、递归创建。
销毁 partner 前先从模型层级脱离，避免 Unity 延迟 Destroy 让同轮枚举重新找到旧对象。

- 实际 Blender 后台测试：P 分离保留资源身份/蒙皮信息；两组独立切换；状态多网格/空状态；保存重开；
  预览恢复；材质分配；所选资源依赖；重复 ID 自动分配；错误不破坏已有输出。
- 用实际 DLL INI 解析器读取 Blender 导出的文件，并求值各状态，验证常显、隐藏、款式和第二组互不干扰。
- 既有 UV/法线/材质槽与增量导出回归测试继续通过。
- 自动测试不代表大世界/UI/换图原生 Renderer 新建与销毁已验收；部署状态和游戏实测结果单独记录。

## 使用与部署记录

开发插件目录：`E:\vscode\EIEM_Blender`，用 VS Code 打开该目录后运行 **Blender: Start**。
包入口 `__init__.py` 与实现 `eiem_blender_addon.py` 来自仓库 `tools/Blender/`，部署时连同 Physics 两个模块一起同步，完整清单见[插件说明](../tools/Blender/README.md)。
本机该目录的 `.vscode/settings.json` 开启了 `blender.addon.reloadOnSave`；保存后自动重载，也可手动
运行 **Blender: Reload Addons**。入口在 **文件 → 导入/导出 → EIEM package** 和
**3D 视图 → N → EIEM → 网格切换**。不要同时运行旁边的单文件副本，以免重复注册。

快速例子：

1. 导入离线 EIEM 包，保存 `.blend`；在原网格上用 `P → 选中项` 分离出上衣、饰品，其他部件留下常显。
2. 物体模式选上衣 → **从所选创建切换组** → 名称“上衣”。插件自动分配一个尚未使用的 F 键并生成显示/隐藏状态。
   如需修改，在当前组旁点击**录制按键**，然后直接按键盘按键或 `Ctrl/Shift/Alt` 组合键；Esc 取消。
3. 选饰品 → 再建“饰品”组。面板持续列出“游戏按键 → 切换组”，无需记忆哪个键属于哪个组。
   多选几个网格一起建组，就会一起显隐。
4. 如需不同款式：复制/制作另一款网格，在上衣组点 **添加款式**，选它后点该状态的 **所选归入**。
   切换顺序是面板列出的状态顺序。对象不得同时属于两个状态；“所选归入”会自动解除旧归属。
5. 状态左侧圆点设置进游戏的初始状态；**预览**只是 Blender 临时显隐，**恢复编辑显隐**撤销预览。
6. 回到物体模式，恢复预览后选中需要保留的所有相关网格/款式及隐藏目标 → **导出所选 mod**
   （或文件 → 导出 → EIEM package）。文件选择页显示实际所选/隐藏/源资源/切换组数量。
   导出到一个新的 mod 文件夹，不覆盖离线源包。
7. 把文件夹放进 `plugin/mods/`。游戏内 F6 切上衣、F7 切饰品；首次更新 DLL 需重新启动游戏。
   同一个源 Mesh 不要同时启用旧测试 mod 和新导出的 mod，否则现有“第一条命中”规则会竞争。

注意：不要保留一个完整原衣服的副本作为“常显”部件，否则它会遮住显隐变化。
LOD0/LOD1 等仍是不同目标；要在其他 LOD 同步切换，就把相应 LOD 的部件也放入同一状态。
游戏快捷键不要与全局刷新/面板键冲突；Blender 不负责修改其他 mod 或全局快捷键。
`.blend` 必须保留，它才是再次编辑状态与重新生成 INI 的工程源。

历史测试和部署结果见[版本记录](archive/release-records.md)。
