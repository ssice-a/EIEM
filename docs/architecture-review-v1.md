## 有意保留的检查与兼容

- 二进制长度、索引范围、Unity 类型、托管数组长度、主线程和对象存活检查属于必要前置条件。
  不按分支数量决定是否删除。
- 正在使用的 EIEMESH v2/v3 Reader、原始骨架 TRS 和坐标标记保留。
  它们是离线资源输入，不是已否定的运行时替换策略；贸然删除会破坏现有工程。
- 原生游戏生命周期 Adapter 保留，但它们只提交同一执行器。
  不为本次清理引入更多角色特判，不承诺当前 hooks 穷尽未知场景。
- 审查范围未发现按 Wulfa/Typhoea 名称、4902 顶点等测试数值驱动正式替换的条件。
  调试记录/测试数据里的名称不是匹配硬编码。

## 做条件/按键功能前仍需解决的真实问题

1. **蒙皮失败没有阻断提交（高优先）**：EiemBuildNativeMesh 忽略 EiemAlignSkinningPalette 的 false。
   应用包含有效蒙皮信息的负例做真实接口回归后改为明确失败；不能继续假设索引相同。
   本轮没有改现已成功的蒙皮算法，以免没有验证就重引入 T-pose/扭曲。
2. **资源退休和多实例所有权（高优先）**：缓存清除主要释放 GC handle，没有完整证明自产
   Unity 原生对象何时可 Destroy；直接在逐项淘汰时 Destroy 可能伤到仍引用它的 Renderer。
   这是反复切换与长期热重载的前置工作，不能靠无限保留缓存掩盖。
3. **跨作用域规则冲突**：单规则集第一条命中，PFB/顶层又可依次修改同一对象。
   条件切换前需明确最终动作如何合成、覆盖以及恢复，不能让遍历顺序成为隐藏协议。
4. **实例登记/恢复粒度**：仅成功命中的顶层模型才登记；首次没有任何规则或新加目标时，
   F10 不会扫描陌生实例。Mesh-only 规则也会捕获材质/骨架快照，恢复可能覆盖游戏后来变化。
   应先明确最小字段所有权及已发现实例的可观察性，再谈任意按键切换。
5. **部分容量是实现限制**：512 骨骼、固定数量材质/partner/owners 等不能当作 Unity 契约。
   INI 字符串超长与引用循环还缺完整诊断，需规划清晰错误而不是截断/猜测。
6. **Blender 骨架编辑**：write_skeleton 仍优先写保存的源 local TRS，原样回传不代表编辑骨骼能生效。
7. **同资源改像素的增量依赖**：材质只比较纹理 section 时，dirty Image 可能没进入导出闭包。
8. **导出失败保护**：prepare_export_root 在充分校验前清理旧输出，后续失败可留下半成品。
   应先计划/校验，再输出与切换。不能在这里再叠自动回退链。
9. **输入错误提示**：部分贴图导入/JSON 元数据仍静默吞错；区分确实可缺省和损坏内容后再收严。

以上是已知未完成项，不是“架构已经不存在问题”。本轮提供正确的配置/更新接口，
并不以新抽象层掩盖这些所有权和作者数据问题。

## 新功能的 Seam

最小方向是：语法前端 → 条件求值/变量状态 → Render 动作 → 主线程重应用。
状态变化走 Reapply，不重新读取整个磁盘；配置变化走 Reload。
现在已经有两种真实输入 Adapter（F10、管理器）和生命周期输入；无需再造通用事件总线。
语句顺序、变量作用域、if 嵌套、按键按下/切换/保持、多个mod冲突等由下一轮语法设计决定。
