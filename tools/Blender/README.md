# EIEM Blender 开发插件

开发目录：`E:\vscode\EIEM_Blender`，在 VS Code 中打开这个文件夹。

目录只需要：

- `__init__.py`：插件发现和注册入口，包含 Blender 要求的 `bl_info`。
- `eiem_blender_addon.py`：完整导入、编辑、导出实现，当前 0.7.0。
- `README.md`：本说明。

仓库源文件位于 `tools/Blender/`。部署新版时同步上述三个文件，不要只更新
旁边的 `E:\vscode\eiem_blender_addon.py`。无需旧版 `eiem_format.py`、
`eiem_export.py`，也不要安装旧 ZIP。

## 开发环境加载

1. 用 VS Code 打开开发目录，运行 **Blender: Start**。
2. 修改代码后运行 **Blender: Reload Addons**。本机开发目录的
   `.vscode/settings.json` 已开启 `blender.addon.reloadOnSave`，保存时自动重载。
3. 文件 → 导入/导出 → **EIEM package**；3D 视图按 N → **EIEM → 网格切换**。

如果修正目录之前已经启动 Blender，当时开发插件列表可能为空；重新运行
Blender: Start 会重新发现入口。不要同时手动运行单文件版，以免重复注册。

## 导入、编辑与导出

- 导入选择 AnimeStudio 离线导出的 EIEM 资源目录中的 `mod.ini`，不是单独的
  FBX，也不是只含一个修改网格的游戏测试 mod。
- 按资源导入网格、共享骨架和 LOD 集合；保存 `.blend` 作为编辑工程。
- 修改网格、材质、贴图；需要按键切换时，选网格，在 N → EIEM 中创建切换组，
  填写快捷键，并将网格分配到显示、隐藏或其他款式状态。
- 选中相关网格，导出到新的 mod 目录。导出器补齐相关依赖并生成 `mod.ini`，
  不会因为导入了整个角色就必须导出全部资源。
- 不要覆盖离线源包；条件 INI 是游戏运行产物，后续编辑请重新打开 `.blend`。

详细操作和验证边界见仓库 `docs/blender-switches.md`。

## 独立 Mod UI、切换按钮与形态键滑条（0.7）

1. 选中 EIEM 网格，在 Blender 原生形态键面板添加相对 Basis 的形态键并编辑。
2. 选中该形态键，进入网格数据属性（绿色三角图标）→ **EIEM 形态键控制** →
   **为当前形态键生成控制滑条**；填写显示名称、默认值和范围。
3. 保存 `.blend`，选择相关网格导出 EIEM package。导出器自动生成形态键数据及
   `Constants`、`UI`、`ui.lua`、`Render` 的 `shape.名称` 绑定，不需要手写 INI。
4. N → EIEM → 网格切换，填写 **UI 开关键**（默认 F8）和 **UI 标题**，与切换组的游戏按键分开。
5. 加载新 DLL 并通过全局刷新读取导出的 Mod；按 UI 开关键打开独立窗口，窗口右上角 × 关闭。
   切换组自动显示款式按钮，形态键自动显示滑条；操作直接更新变量，无需 F10。
   INSERT 仍只开插件管理面板。Lua/INI 文件修改后才使用全局刷新（默认 F10）。

同一个 .blend 更新插件后重新导出，会生成新版 INI/Lua；不用重做网格或形态键控制数据。
旧 `[Slider...]` 配置已移除，不保留 DLL 兼容分支。多个 Mod 的同名变量互不影响；
UI 键可以跨 Mod 共用，符合各自 condition 的窗口共同响应；导出器不自动生成视锥检测条件。
需要复杂布局可编辑生成的 `ui.lua`，但再次自动导出会覆盖该生成脚本，先另存自定义脚本。

切线规则：源资产必须正确解码并保留原切线；只有新增几何才生成切线。
不能用最终法线 + UV0 重算结果冒充源数据。115/120 缺失指修复前调查，详见顶点数据契约。

仅支持相对 Basis、无顶点组遮罩的形态键；多帧源形态键暂不生成滑条。
作者数据、导出和权重接口已测试，终末地自定义 GPU 管线的实际形变尚未游戏验收；
新增形态键也不会自动重建游戏专用法线/切线增量。具体边界见仓库 `docs/shape-controls.md`。
