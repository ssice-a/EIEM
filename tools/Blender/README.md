# EIEM Blender 开发插件

当前能力、未完成接入和历史记录：[文档索引](../../docs/README.md)。

开发目录：`E:\vscode\EIEM_Blender`，在 VS Code 中打开这个文件夹。

目录只需要：

- `__init__.py`：插件发现和注册入口，包含 Blender 要求的 `bl_info`。
- `eiem_blender_addon.py`：导入、编辑、导出入口，仓库源码版本 0.31.0。
- `eiem_blender_controls.py`：形态键与网格切换的作者数据、预览和导出计划，必须一起分发。
- `eiem_physics_authoring.py`、`eiem_physics_document.py`：Physics 面板、辅助体和资源读写，必须一起分发。
- `eiem_physics_native.py`、`eiem_physics_source.py`：源物理图保留、编辑和独立 v2 导出，必须一起分发。
- `README.md`：本说明。

仓库源文件位于 `tools/Blender/`。部署新版时同步上述八个文件，不要只更新
旁边的 `E:\vscode\eiem_blender_addon.py`。无需旧版 `eiem_format.py`、
`eiem_export.py`，也不要安装旧 ZIP。

## 开发环境加载

1. 用 VS Code 打开开发目录，运行 **Blender: Start**。
2. 修改代码后运行 **Blender: Reload Addons**。本机开发目录的
   `.vscode/settings.json` 已开启 `blender.addon.reloadOnSave`，保存时自动重载。
3. 文件 → 导入/导出 → **EIEM package**；3D 视图按 N → **EIEM → 网格切换**。

如果修正目录之前已经启动 Blender，当时开发插件列表可能为空；重新运行
Blender: Start 会重新发现入口。不要同时手动运行单文件版，以免重复注册。

## 导入、编辑与导出

- 导入选择 AnimeStudio 离线导出的 EIEM 资源目录中的 `mod.ini`，不是单独的
  FBX，也不是只含一个修改网格的游戏测试 mod。
- 按资源导入网格、共享骨架和 LOD 集合；保存 `.blend` 作为编辑工程。
- 修改网格、材质、贴图；需要按键切换时，选网格，在 N → EIEM 中创建切换组，
  录制快捷键。只调整整组的眼睛显隐后记录款式快照；同一网格可在同组多个款式中可见。
  支持主键盘、小键盘数字与运算键，以及 `Ctrl/Shift/Alt` 修饰键组合；小键盘 Enter 与普通 Enter
  在 Windows 热键接口中统一作为 `ENTER`。
- 只选中要交给 Mod 处理的网格，导出到新的 mod 目录；不自动补选同源物体或切换组成员。
  相机图标开启：正常导出网格及所需修改材质/贴图。相机图标关闭：生成隐藏动作，
  不写该物体的网格、材质或贴图文件。N → EIEM 的“游戏隐藏（相机）”编辑同一开关。
- 未选中的独立源 Mesh 不生成规则，沿用游戏渲染。眼睛/显示器只影响 Blender 编辑预览，
  不产生游戏隐藏动作。需要切换的所有款式请一起选中，空状态仍可表示隐藏。
- 同一个原 Mesh 拆成几块后，仍然共用一个源命中目标。要保留的拆分部件必须一起选中；
  不选某一块不能让游戏单独恢复原 Mesh 中对应的那部分面。
- 不要覆盖离线源包；条件 INI 是游戏运行产物，后续编辑请重新打开 `.blend`。

详细操作和验证边界见仓库 `docs/blender-switches.md`。

只有一个隐藏目标时，导出结果可以只有 `mod.ini` 中的一个 Render 块和 `handling=skip`，
不需要 `.mesh`、`.mat` 或 PNG。对同源拆分物体混合显隐时，隐藏原件并仅装配所选的相机开启部件。

## 物理骨骼作者工具（0.30.3）

AnimeStudio 正常导出的 `.eiem` 目录若含 `physics/components.json`，在包导入窗口勾选
“导入物理骨骼与碰撞体”即可一起导入。插件会把原生物理实际需要、而渲染 Skeleton 未收录的
末端物理节点、组件 owner 和碰撞体 Transform 合并到同一个共享 Rig；不会把 Prefab 的 IK、VFX、
Mesh 容器等无关 Transform 当成骨骼。Typhoea 正常包实测一次导入 62 个 Mesh、1 个共享 Rig、
11 个原生物理组、27 个碰撞体和 192 个物理相关 Transform。

每次 package 导入会在顶层 `EIEM` 下建立独立集合，内部为 `Meshes / Skeletons / Physics`，所以连续导入
多个 package 不会再把同名 LOD 混在一起。已有 Mesh/Rig 时不要再次导入完整 package：选中目标 EIEM Rig，
在本面板点击“导入游戏源物理”并选择 `physics/components.json`。

1. 在共享 Rig 的编辑/姿态模式选择连续的两根或更多骨骼，N → EIEM → **物理骨骼** → **新建** → **从所选骨骼新建物理链**。
   同时选择多条分支时，每条分支的第一根骨骼分别成为 FIXED，后续骨骼成为 MOVE；它们在同一物理组中共享参数。
   分支共同的骨架父级不会被自动加入物理组，这与游戏原生 `rootBones` 结构一致。
2. 设置固定/运动/忽略节点、组参数和节点碰撞半径。节点基础半径位于组 Empty 的对象属性；
   日常只调整根端倍率、末端倍率和线性/平滑变化；需要非均匀变化时再展开“高级关键点”，按链位置 0～1
   精确编辑中间点。视图球体会自动按真实尺寸刷新。
   从游戏源组粘贴后，作者组会使用与游戏原生组相同的固定顺序参数界面；下拉框一次选择并编辑九类位置曲线之一。
   完整源字段只用于只读检查，模板通过复制/粘贴一次填充，不要求用户逐项输入。
   在 Rig 上选好绑定骨骼后还可添加独立球体或胶囊。
   位移/旋转工具编辑局部变换，面板编辑半径与两端球心间距。组 Empty 的“碰撞集合”可选择、移除或加入
   同一 Rig 已导入的作者/游戏源碰撞体；复制参数和粘贴参数会同时复制这份碰撞集合。
3. 保存 `.blend`。回到物体模式，选中所需物理组，点击 **导出所选物理组**，输出 `.physics` 及相邻 `skeletons/`。
4. **导入 Physics 作者包** 可读回文件：选中相同 Rig 时校验并复用，未选 Rig 时创建独立骨架。
5. 新增骨骼可在 Rig 上选连续骨链后点击 **新建** → **复制所选骨骼并新建物理链**。副本保留静止层级并接回原父级，
   但不复制源身份，也不自动改网格权重；需要运动的顶点由用户明确转移给副本。
6. 选中目标 Mesh 后点击**导出所选 mod**；也可以同时显式选择新增作者物理组。若可见 Mesh 对某组节点骨骼
   有正权重，该组会作为真实依赖自动加入，共享 Rig 自动写出，同 Rig 的每个 Render 引用同一 Physics。
   不使用作者物理骨骼的 Mesh 仍只增量导出 Mesh；作者球体/胶囊及引用的游戏源球体/胶囊会随
   作者 v5 输出。原生无限平面和完整原生 v2 组继续使用独立作者导出。

旧 v1 无碰撞体 `Render.physics` 已在主模型、角色 UI 和 NPC 实机验证；0.30.3 新导出使用作者 v5。除
`radius.value/useCurve/AnimationCurve` 与 v4 完整参数模板外，v5 胶囊还保存首端/末端半径、两端球心距离和
中心对齐开关。DLL v74 实机已按骨骼创建 5 个原生球/胶囊、写入物理组碰撞列表并进入 running Team；
DLL v75 实机确认伙伴包围盒有效、全部物理节点进入伙伴骨骼表，12 个 MOVE 节点持续运动；可见裙摆仍未响应。
旧 v79 日志已确认作者 Physics 到达 ready、12/12 MOVE 节点变化且 5 个碰撞体进入实例；之后一次只选 Mesh 的
覆盖导出删掉了 Physics。0.30.3 已修正这项依赖推导，但必须重载插件并重新导出后才能恢复当前游戏包。
详细格式、依赖、限制和验证见仓库 `docs/physics-authoring-v1.md`。

旧开发包 `bin/EIEM_Blender-0.11.0-physics-authoring.zip` 仅包含旧 v1，不代表当前源码版本。

## 源物理作者数据（0.30.3，离线）

通过“导入源物理”选择解包的 `components.json`，或者在 Mesh 包导入时勾选默认关闭的物理选项。
源图、参数曲线、原始字节和共享碰撞引用保存在 `.blend`；使用独立导出保存 `.physics` 及骨架依赖。
物理侧栏提供**复制参数 / 粘贴参数**两个直接按钮。原生组之间复制全部匹配的可编辑数值与曲线字段；粘贴给
新增作者组时把完整模板和源组使用的碰撞集合保存在组 Empty 内。带完整模板的作者组与原生组共用同一套固定顺序参数 UI、
角度锥预览和九类位置分布参数；“源数据检查”可筛选、分页查看全部字段，但不再作为第二套编辑入口。导出 v5 时主界面的编辑值
会覆盖模板中的对应字段，其余数值、开关、枚举、`gravityDirection` 与曲线保持模板值。曲线资源完整保存关键帧、
切线、权重、Infinity/RotationOrder 元数据和曲线开关；当前 DLL 写入关键帧、切线、权重、基础值和曲线开关，
Infinity/RotationOrder 仍只随资源保留。球、胶囊和无限平面按源字段及 MagicaCloth 公共 API 合同显示；面板列出绑定骨骼、引用次数
和引用组。真实 Typhoea 样本为 11 组、27 碰撞体、556 Transform。

原生胶囊的 `size.z` 是包含两个圆头的外部长，不是两端球心距离。面板同时显示这两个值；Start 位于局部
方向轴的正端，End 位于负端，`reverseDirection` 会翻转该轴。关闭 `alignedOnCenter` 时 Start 球心就是
`center`，另一端球心距离为 `max(length-startRadius-endRadius, 0)`。

Physics 集合分为 `Groups / Colliders / Visuals`。默认只显示当前组和它引用的碰撞体，并关闭穿透模型显示；
“视图范围”可切换为全部组、全部碰撞体、全部或隐藏。“样式”默认使用低面数实体球、实体骨链连接和半透明
碰撞体，也可切回诊断线框。一个物理组可能含多个根和分支；组面板逐条列出根链并可单独选择，同时明确列出
该组实际引用的球、胶囊或平面碰撞体。碰撞体是单独组件且可被多组共享。

蓝色 MOVE 点和橙色 FIXED 点的球面现在表示原生链节点的碰撞半径，不再使用统一大小的节点标记。每个点的
显示半径为 `radius.value × radius.curve(depth)`；`radius.useCurve=false` 时倍率为 1。depth 与下述角度限制使用
同一套累计骨段长度规则。灰色 IGNORE 点只保留小型拓扑标记，不赋予物理半径。切换实体/线框或修改基础半径、
半径倍率或高级关键点后，当前组预览会自动重建。本阶段没有改变单独的球、胶囊、平面碰撞体编辑。

启用原生 `useAngleLimit` 的组还会显示黄色半透明角度锥。锥尖位于父节点，锥轴沿静止姿态的父→子边；每根
MOVE 骨段的半角为 `limitAngle.value × curve(depth)`。这里的 depth 与游戏构建一致：沿 MOVE 父链累计骨段
长度，再除以本组最长根到末端长度，而不是骨骼层数。关闭 `useAngleLimit` 时不显示锥体；曲线本身未静音只表示
`limitAngle.useCurve=true`，两者不能混为一个开关。锥体是静止基准姿态的作者预览，运行时当前动画基准仍会受
`animationPoseRatio` 影响。

新增作者组的角度锥直接使用 Rig 的 Blender 局部坐标，与节点半径球和绿色骨链重合；只有导入的原生 v2
源图预览才执行 Unity→Blender 基变换。0.26.2 修正了作者锥体被重复转换后落到角色脚边的问题。

每个物理 Group/Collider Empty 的 EIEM RNA 属性是唯一源数据，骨骼只保存身份与静止变换。选中 Empty 后在
**对象属性 → EIEM 物理参数**中编辑，不需要在侧栏寻找另一份参数。九类常用曲线由下拉框选择，面板一次只显示
一类参数的基础值、根端倍率、末端倍率和线性/平滑变化；“使用位置曲线”直接对应 `useCurve`。只有源曲线含
中间关键点或作者需要增加局部变化时，才展开“高级关键点”编辑链位置与倍率，不再显示单独的大型曲线控件。
半径和角度曲线改动会实时刷新节点半径球与角度锥，并在导出时写回原字段。未修改的源曲线保留原关键帧、
切线和权重；实际编辑倍率或关键点后，以当前控制点重新生成无权重切线。选中当前组的一根 Rig 骨骼时，侧栏会显示
该节点的 FIXED/MOVE 角色、归一化链位置、当前参数倍率及实际值，并可在该位置增加关键点。完整 TypeTree 路径只在折叠的只读
“源数据检查”中显示，复制模板会一次填入这些保留值。源 JSON 只解析一次，普通参数变化不重建几何。

物理侧栏首层只有**当前组、新建、复制参数、粘贴参数、查看**。显示、链结构和文件操作默认折叠。新建作者链时，在 Rig
编辑或姿态模式选择一棵连续骨链，然后点击**新建 → 从所选骨骼新建物理链**；顶端成为固定节点，其余为
运动节点。后续新增同一链的后代骨骼后，在折叠的**链与碰撞体**中点击**将所选骨骼加入当前链**。一个作者
组可以包含多个独立根分支，各分支首骨为 FIXED，并共享组参数。创建、加入、移除都会立即重建显示，修改骨架静止姿态后也会在
退出编辑模式时自动刷新。原生 v2 的拓扑保持只读，可作为参数和结构参考，不在 Blender 中猜写 Selection 映射。

导入骨骼的 `head` 是游戏 Transform 的原点，`tail/roll` 用于表达该 Transform 的局部旋转；游戏源骨骼的局部
`+Y` 不保证指向子节点。判断物理链走向应看绿色“层级连线”和父子节点的 head，不要把源骨骼强制连接、统一
重算 roll 或把 tail 拉到子节点。对于新增骨骼，head 及父级决定节点局部位置，tail 方向和 roll 会进入导出的局部
旋转；骨骼显示长度本身不是 Physics 参数。面板中的“Blender 骨骼外形”只改变视图形状，不改变这些数据。
0.13.0 保存的旧工程仍可读取；选中其 Rig/物理对象后点击“整理当前 Rig 的物理集合”，即可把旧的平铺辅助对象
迁移到三个分类集合。该操作只改变 Blender 场景组织和编辑显隐，不修改源组件身份或导出内容。
详细操作、格式与限制见[源作者 v2](../../docs/physics-authoring-v2.md)。

原生源球体/胶囊现在可转为作者 v5 碰撞记录并进入组合 Mod；无限平面与完整原生 v2 图仍只用于导入、可视化、
复制和独立保存。常规 Mesh 与作者物理均按选择增量输出，不以 PFB 限定消费者。
0.31.0 的运行文件同步后，已运行的 Blender 会话需要执行 **Blender: Reload Addons** 才会载入新版。
旧 ZIP 和已经打开的 `.blend` 不会自行改写；旧场景可用上面的整理操作迁移物理集合。

## UV 接缝与导出顶点（0.8.2）

- `UV0`、`UV2` 而没有 `UV1` 是合法布局，不要补造或重命名通道。
- 同一 Blender 顶点在不同面上可以有不同 UV、法线或顶点色。导出器按这些面角数据
  自动生成顶点副本，只改变输出文件，不拆开或修改 `.blend` 中的网格。
- 位置、原切线及符号、多维 UV 的 Z/W、权重、标准形态键增量使用同一源顶点映射。
  不重排骨骼调色板、不删除零权重骨骼槽，也不通过平均 UV/法线来消除接缝。
- 输出顶点数可能增加，三角形数量不因此增加。未知布局的游戏专用 additional-normal
  数据仍在需要重映射时明确报错，不冒充已经支持；详见 `docs/vertex-data-contract.md`。

## 切线导出（0.11.1）

- 原模型已有可用的 `EIEM_Tangent` / `EIEM_TangentSign`：保留其数值及符号，删面不触发统一重算。
- 新增或外部网格没有切线：保留名为 `UV0` 的贴图 UV 和最终法线，导出时自动生成切线。
  合并后属性存在但新顶点数据为零时，也只补缺失部分，不覆盖其余有效源切线。
- 生成使用当前 Blender 自定义法线与明确的 `UV0`，不使用当前激活的其他 UV 层；
  镜像 UV 切线接缝自动拆分输出顶点。不会向 `.blend` 写回生成数据，也不需要增加 INI 配置。
- 没有 UV0 且完全没有切线的网格仍可按无切线导出；部分源切线损坏又无 UV0 时明确报错。
  属性只有向量或只有符号属于不完整数据，仍需修正。需要生成切线的 N-gon 请先三角化。
- 旧工程缺失源切线时，重算得到的是新生成数据；想恢复原生数据则需重新解包，不能自动找回。
  本功能不生成游戏专用描边 UV2 或新增形态键的法线/切线增量。

详细数据契约及回归入口见 `docs/vertex-data-contract.md`。仓库升级后需同步/重载实际使用的插件，再重新导出 Mod；
本次文件布局不变，不要求修改 DLL 或游戏 INI。

## 一个部位使用共享骨架（0.8.3，配套 DLL v43）

- 外部网格沿用目标 EIEM 物体的来源信息，Armature 修改器指向角色的同一共享骨架；
  顶点组名称对应该骨架的骨骼，不需要局限于原部位使用的少数骨骼。
- 原骨骼槽和绑定矩阵不重排、不删除；导出器自动追加额外骨骼，DLL 按完整骨骼路径解析当前实例。
  无需手写骨骼索引或 INI。已有旧工程直接重新导出，不需要重新拆网格、重画权重。
- 当前二进制每顶点保存 4 个影响；超过 4 个时保留最强四个并归一化，控制台报告数量。
  未找到的正权重骨骼或有面顶点没有权重时明确报错，不静默写成全零。不会修改 Blender 原权重。
- 新导入包将其他部位的原绑定数据存于共享骨架；删掉那些部位物体也不会丢失参考绑定。
  旧工程优先读取仍保留的源物体元数据。未使用过的骨骼使用源骨架绑定姿态生成新槽；
  全新骨骼及骨架动画修改不属于本次“沿用现有骨架”的支持范围。
- 旧导出中已丢掉的权重不能靠 DLL 自动恢复：需要重新导出 `.mesh`。DLL 更新需要重启游戏，
  F10 只重读资源/配置，不能更新 DLL。当前实际游戏蒙皮结果仍待验收。

## 新增共享骨架节点（0.10.0，配套 DLL v48）

- 沿用已有共享 Armature，在编辑模式 `Shift+A` 新建骨骼，设置父级、位置和旋转，再给网格赋权重。
  不要直接复制带源身份属性的旧骨骼；重复源路径会报错，不自动猜测新旧身份。
- 导出时同时选择要处理的网格和共享 Armature；自动输出一个 `.skeleton` 及 Render 的 `skeleton=`。
  多个部位共用这份骨架，无须分别创建骨架或手写骨骼索引。
- 原骨骼槽（包括零权重槽）和绑定矩阵保留；新增骨骼追加到 Mesh 局部表。
  对已有源骨骼修改绑定姿态、父级暂不支持，导出时明确报错。
- 新骨骼跟随父节点变换，不自动生成独立动画或物理。游戏自定义 GPU 蒙皮仍需验收，
  完整实现和构建记录见仓库 `docs/skeleton-driving.md`；仓库升级不代表安装目录已更新。

## 款式快照、独立形态按键与可选 Mod UI（0.29）

1. 选中 EIEM 网格，在 Blender 原生形态键面板添加相对 Basis 的形态键并编辑。
2. 新增形态键导出时自动生成控制变量，以 Blender 当前权重为作者默认值，无需先建立 UI。
   网格数据属性（绿色三角图标）→ **EIEM 形态键控制** → **刷新新增形态键列表**，可查看、禁用控制。
   源游戏已有键默认继续由游戏驱动；需要接管时选中它，点击 **接管当前形态键**，填写默认值和范围。
3. 需要简单 UI 时，在 N → EIEM → 网格切换勾选 **生成简单 UI**，填写标题和自己选择的快捷键。
   没有默认 UI 快捷键；留空时生成常显、无 × 的模板。不开启模板仍可正常导出资源与控制变量。
4. 保存 `.blend`，选择相关网格导出 EIEM package。勾选模板时额外生成 `UI`、`ui.lua`，
   有按键时生成普通 Key 和 `$ui_open`；窗口布局、显示条件和关闭行为都在这个 Lua 文件里。
5. 加载新 DLL 并通过全局刷新读取导出的 Mod；按**自己配置的按键**打开模板窗口，× 只关闭窗口。
   切换组显示款式按钮，形态键显示滑条；操作更新模型变量，关闭 UI 不会重置这些模型变量。
   INSERT 仍只开插件管理面板。Lua/INI 文件修改后才使用全局刷新（默认 F10）。

网格切换组只记录组内 Mesh 的眼睛显隐。款式使用紧凑列表显示；按住每行左侧手柄上下拖动可调整游戏内
循环顺序，预览、导出 Key 值列表和简单 UI 使用同一顺序。列表“−”删除当前选中款式并至少保留两个；
组名右侧的**删除当前组**只删除切换组和款式快照，不删除 Mesh。
形态键在网格数据属性 → **EIEM 形态键控制**中单独配置：可分别录制增大按键和减小按键，并设置变化速度。
增大键始终把目标设为最大值，减小键始终把目标设为最小值；同一方向重复按下不会反向。DLL 按“变化速度/秒”
逐步逼近目标，例如速度 0.5 时，0→1 约需 2 秒。形态键仍保留普通独立变量和可选 Lua 滑条。

同一个 .blend 更新插件后重新导出，会生成新版 INI/Lua；不用重做网格或形态键控制数据。
0.9 导出的形态键和切换变量带 persist，玩家调整值保存在该 Mod 的 `state.ini`；F10、换图和重启保留。
模板里的 **恢复默认值** 重设模型变量，不关闭窗口。没有模板时，可退出游戏后删除 state.ini 恢复作者默认值。
修改 Blender 默认值并重导出不会强制覆盖已有玩家值；变量身份随 .blend 保存，不依赖导出顺序。
旧 `[Slider...]` 配置已移除，不保留 DLL 兼容分支。多个 Mod 的同名变量互不影响；
UI 可以不依赖按键、根据变量显示或互相打开；一个 Lua 可以画多个窗口。显示条件写在 Lua，不写在 UI 块。
普通 Key 的 `scope=both` 让按键在游戏和 UI 有焦点时都能更新变量；导出器不自动生成视锥检测条件。
需要复杂布局可编辑生成的 `ui.lua`，但再次自动导出会覆盖该生成脚本，先另存自定义脚本。

## 独立导入其他角色材质（0.9）

1. 选中要指定材质的网格，进入 **材质属性**，选择要更换的材质槽。
2. 在 **EIEM 材质** 面板点击 **导入 EIEM 材质**，选择其他角色离线导出的 EIEM `.mat`。
   保留它所在资源包的 mod.ini 和贴图目录；不要只搬一个依赖本地贴图的 .mat 文件。
3. 插件新建材质数据块并放进当前槽，载入真实 source、参数和贴图路径；不覆写原材质数据块。
   在该面板修改贴图路径或参数，再按原流程导出所选网格。未改参数/贴图沿用源游戏材质，不重复打包。

支持 EIEMMAT，不是任意 Unity YAML .mat，也不会把普通 Blender 节点材质编译为游戏 Shader。
手工改 source 路径不会自动查出另一材质参数；完整更换请用上述导入按钮。

仅支持相对 Basis、无顶点组遮罩的形态键；多帧源形态键暂不生成滑条。
作者数据、导出和权重接口已测试，终末地自定义 GPU 管线的实际形变尚未游戏验收；
新增形态键也不会自动重建游戏专用法线/切线增量。具体边界见仓库 `docs/shape-controls.md`。
